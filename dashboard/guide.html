Setup Guide

Add Relay to your Discord server and let your team run Cursor cloud agents on your GitHub repos — or chat with ChatGPT, Gemini, and Claude — using /agent. Setup is admin-only and one-time (about 5 minutes). Regular members don't set up anything — they just type /agent.

What this bot does: it runs Cursor Cloud Agents that clone a GitHub repo, work on it, and can open pull requests — all from Discord. So you'll connect a Cursor API key and at least one repo.

What you'll need

  • Manage Server permission on your Discord server.
  • An API key for at least one AI provider (bring your own):
    • Cursor for cloud agents that work on a repo and open PRs — needs a Cursor API key and a GitHub repo connected to Cursor.
    • OpenAI (ChatGPT), Google Gemini, Anthropic (Claude), or OpenRouter (many free models) for chat answers in Discord — no repo required.

Step 1 — Add the bot to your server

  • On the dashboard, click Sign in with Discord and authorize.
  • Find your server and click Add to Discord. Relay prefills that server for you; approve the install to continue setup automatically.
  • Servers where Relay is already installed show Configure instead.

Step 2 — Connect Cursor to GitHub (once)

Cursor's cloud agent needs access to your repo to clone it and open PRs.

  • Go to cursor.com/dashboard → Integrations → GitHub.
  • Install/authorize the Cursor GitHub App on the account/org that owns your repo.
  • Grant access to the repo(s) you'll use (or "All repositories").

Step 3 — Add an AI provider key

On the dashboard, select your server, then under AI provider keys choose a provider, paste your key, click Save key, then Test connection (should say Connection OK). Add a key for each AI you want to use.

Step 4 — Create a project

A "project" maps an AI (and who can use it) to your server. Pick a Provider first — the form then shows the right fields. Add as many projects as you like.

Getting Discord IDs

Enable User Settings → Advanced → Developer Mode, then:

  • Role ID: Server Settings → Roles → right-click a role → Copy Role ID.
  • Channel ID: right-click a channel → Copy Channel ID.
@everyone doesn't work as an allowed role. Discord never lists the @everyone role on members, so it can't be matched. To allow your whole team, create a real role (e.g. AI Access), assign it to members, and use that role's ID.

Multiple repos

Create one project per repo. Members choose which repo by:

  • Channel: map each repo to its own channel(s), or
  • Command option: leave channels blank and pass project: (with autocomplete), e.g. /agent prompt: ... project: api.

Step 5 — Use it

In a mapped channel (with your allowed role):

/agent prompt: summarize what this repository does

You'll see a Started embed that updates to Running → Finished.

CommandWhat it does
/agent prompt:<text> [project:<slug>]Start, or continue this channel's agent
/agent-new prompt:<text>Always start a fresh agent
/agent-cancelCancel the agent running in this channel and unlock it
/agent-statusRecent agents/runs in this channel/thread
/agent-projectsProjects you can access

/cursor* are aliases for the same commands.

Troubleshooting

MessageCause & fix
"This server is not configured yet."Finish Steps 1–4 in the dashboard.
"You do not have an allowed role…"Your role isn't in the project's allowed roles. @everyone won't work — use a real role ID.
"No cursor API key is configured…"Add and save your Cursor key (Step 3).
Save says "Invalid project"Repo URL must be https://github.com/owner/repo; role/channel IDs must be numeric Discord IDs (17–20 digits).
"The SCM integration does not have access to repository…"Connect the Cursor GitHub App to that repo (Step 2).
"Discord is rate-limiting the server list."Wait ~60s and refresh; avoid rapid re-sign-ins.

Limits & notes

  • Each user can start a limited number of new agents per hour (default 5); follow-ups are unlimited.
  • One active run per channel+project at a time — wait for it to finish, or run /agent-cancel to stop it and unlock the channel.
  • Follow-up prompts in the same channel continue the same agent; use /agent-new to force a fresh one.
